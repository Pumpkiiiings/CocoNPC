Every CocoNPC command lives under `/coconpc`, aliased to `/npc`.

```bash
/coconpc <subcommand> [arguments...]
```

---

## Permissions

`CocoNPC.admin` is a parent of every node below, so granting it alone is enough for a full
administrator. Each subcommand also has its own node, so you can hand out narrower access.

| Subcommand | Permission |
| :--- | :--- |
| `create` / `spawn` | `CocoNPC.spawn` |
| `list` | `CocoNPC.list` |
| `tp` / `teleport` | `CocoNPC.tp` |
| `tphere` | `CocoNPC.tphere` |
| `delete` | `CocoNPC.npc.delete` |
| `edit` | `CocoNPC.npc.edit` |
| `action` | `CocoNPC.action` |
| `pose` | `CocoNPC.pose` |
| `resize` | `CocoNPC.resize` |
| `item` / `equip` | `CocoNPC.item` |
| `skin` | `CocoNPC.skin` |
| `clone` | `CocoNPC.clone` |
| `viewdistance` | `CocoNPC.viewdistance` |
| `reload` / `preload` | `CocoNPC.reload` |
| `setkey` | `CocoNPC.admin` only |

All nodes default to operators. `setkey` deliberately has no narrow node — it writes an API
credential, so it stays admin-only.

`CocoNPC.npc.edit` is also what gates shift + right-clicking an NPC to open its editor.

Tab completion only suggests subcommands you actually have permission to run.

---

## Console support

Commands must be run by a player. They resolve positions from where you are standing and
open GUIs in your inventory, neither of which the console has.

<Callout type="info">
  `execute as <player> run coconpc ...` does not work around this. Paper keeps the console
  as the command's sender, so the command still refuses.
</Callout>
