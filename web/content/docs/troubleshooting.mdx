## Plugin Loading & Startup

### "Missing dependency: PacketEvents"
**Cause:** PacketEvents is a hard requirement for packet-based entity rendering.  
**Fix:** Download and install [PacketEvents 2.13.0+](https://ci.codemc.io/job/retrooper/job/packetevents/) into your server's `plugins/` folder and restart.

### "Unsupported class file major version"
**Cause:** Mismatched server Java version. Minecraft 1.21.x requires Java 21, and 26.x requires Java 25. CocoNPC is compiled with Java 21 compatibility.  
**Fix:** Update your server runtime to Java 21 or newer (`java -version`).

## Animations

### Animation does not play or limbs don't move
**Check the following:**
1. **Bone Names:** Make sure your Blockbench model groups are named exactly:  
   `head`, `body`, `right_arm`, `left_arm`, `right_leg`, `left_leg`.  
   Any other names or custom bone structures will not be mapped to player limbs.
2. **File Location:** Put your `.bbmodel` or `.json` file inside `plugins/CocoNPC/animations/`.
3. **Reload:** Run `/coconpc reload` to register newly added animation files. Check your console log to verify how many animations were loaded.
4. **Animation Name:** Animation names in `/coconpc animate <id> <name>` are case-insensitive, but must match the animation title inside Blockbench (e.g. `idle`, `walk`, `wave`).

### Animations stopping after server restart
**Fix:** Update to CocoNPC **v1.2.1** or newer. Starting in v1.2, running `/coconpc animate <id> <name>` automatically saves the animation in `plugins/CocoNPC/npcs/<id>.yml` and loops continuously across restarts and world reloads.

## Skins & Appearance

### "Skin generation failed" / "No MineSkin API key set"
**Cause:** Generating new player limb textures requires contacting the MineSkin API.  
**Fix:** Get a free API key at [mineskin.org/account](https://mineskin.org/account) and apply it using `/coconpc setkey <key>`. Previously cached skins in `skins.yml` continue to work without a key.

### Spawning a new skin is slow
**Explanation:** This is normal for the very first time a skin is spawned. CocoNPC slices the skin into 11 individual limb textures and uploads them sequentially to avoid rate limits. Once uploaded, the textures are cached in `skins.yml` and all future spawns of that skin will be instant.

### Arms or body look distorted
**Explanation:** CocoNPC automatically detects and converts 3-pixel slim ("Alex") skins to classic 4-pixel layouts. Non-standard skins with transparent body regions or incorrect dimensions can cause artifacts. Use standard 64x64 Minecraft skins.

## Actions & Interactions

### `[server]` does not connect on Velocity
**Fix:** In v1.2+, CocoNPC natively supports Velocity proxies via the `velocity:player_info` plugin messaging channel, as well as BungeeCord proxies. Ensure your proxy has player messaging enabled and server names match your proxy's `velocity.toml` configuration.

### `[require_money]` always blocks actions
**Cause:** `[require_money]` checks player balances using PlaceholderAPI's `%vault_eco_balance%`.  
**Fix:** Ensure you have both **PlaceholderAPI** and the **Vault** expansion installed (`/papi ecloud download Vault` followed by `/papi reload`). If no economy plugin is available, set `require-money-strict: false` in `config.yml`.

### An action prints `{player}` literally
**Fix:** Use `<player>` or `%player_name%`. `{player}` with curly braces is not an evaluation token.

## Bedrock Players (Geyser)

### Bedrock players cannot see or click NPCs
**Explanation:** CocoNPC creates NPCs using Minecraft Display Entities. Bedrock Edition clients connecting through Geyser currently do not render Display Entities. For this reason, interactions by Bedrock players are blocked by default to prevent invisible click exploits. This requires **Floodgate** for Bedrock player detection.
