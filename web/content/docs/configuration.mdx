## File Structure

All plugin data and configuration files are located inside `plugins/CocoNPC/`:

```text
plugins/CocoNPC/
├── config.yml          # Core settings (MineSkin key, view distance, editor)
├── messages.yml        # Customizable messages and prefixes (MiniMessage format)
├── skins.yml           # Cache of generated limb textures
├── cooldowns.yml       # Active player action cooldowns
├── npcs/               # Individual configuration file per NPC (named by ID)
│   ├── 1.yml
│   ├── 2.yml
│   └── 3.yml
├── animations/         # Drop your Blockbench .bbmodel or .json animation files here
├── skins/              # Drop custom 64x64 .png skins here
└── menus/              # GUI layout configurations
    ├── npc_editor.yml
    └── hologram_editor.yml
```

<Callout type="warn">
  Never share your `config.yml` publicly without clearing your `mineskin.api-key`.
</Callout>

## config.yml

```yaml
mineskin:
  # Required to generate new skins. Get one free at https://mineskin.org/account
  user-agent: "CocoNPC"
  api-key: ""

npc:
  # Maximum distance (in blocks) at which NPCs are rendered to players.
  # Lower this on high-traffic hubs to save packet bandwidth.
  view-distance: 48

editor:
  rotation-step: 5.0
  precision-rotation-step: 1.0
  translation-step: 0.05
  precision-translation-step: 0.01

bedrock:
  # Bedrock clients (Geyser) do not render Minecraft Display Entities.
  # Blocks Bedrock players from clicking invisible entities.
  block-interactions: true
  notify-blocked: true

actions:
  # If true, [require_money] blocks actions if Vault/PAPI is missing.
  require-money-strict: true
  # Strips dangerous injection characters from console commands.
  console-blocked-characters: [";", "|", "&"]
```

### Key Options Explained

- **`mineskin.api-key`**: Essential for generating new skins. Set this with `/coconpc setkey <key>` or edit `config.yml` directly. Once a skin is generated, it is cached in `skins.yml` and never needs to contact MineSkin again.
- **`npc.view-distance`**: Minimum 8 blocks. Can also be updated live with `/coconpc viewdistance <number>`.
- **`editor`**: Step increments used when scrolling in the in-game 3D editor (degrees for rotation, blocks for translation). Sneaking activates the precision steps.
- **`bedrock.block-interactions`**: Protects Bedrock players connected via Geyser from exploiting or accidentally interacting with invisible display entities. Requires Floodgate for player detection.

## messages.yml

Controls all plugin text, error messages, and system notifications. Supports Adventure [MiniMessage](https://docs.advntr.dev/minimessage/format.html) formatting.

```yaml
PREFIX: "<dark_gray>[<yellow>CocoNPC<dark_gray>]<light_purple>! "
NO_PERMISSION: "{prefix}<red>You do not have permission."
SPAWNED_SUCCESS: "{prefix}<gray>Spawned in <yellow>{time} <gray>seconds."
```

If you ever want to reset a specific message, delete its line and reload — the plugin will regenerate it with the default text.

## npcs/&lt;id&gt;.yml

Each NPC has its own dedicated `.yml` file in `plugins/CocoNPC/npcs/`. Everything about that NPC is saved here:

```yaml
uuid: 3f2b8c1a-4d2e-4f12-98ab-123456789abc
id: 1
size: 1.0
animation: wave          # Active Blockbench animation (auto-resumes on restart)
location:
  world: world
  x: 100.5
  y: 64.0
  z: 200.5
  yaw: 180.0
  pitch: 0.0
skin:
  head: aHR0cHM6...
  body1: aHR0cHM6...
hologram:
  lines:
    - '<gold><bold>QUEST GIVER'
    - '<gray>Click to talk'
  billboard: CENTER
hands:
  right:
    material: DIAMOND_SWORD
  left: {}
actions:
  - '[animate] 1 wave'
  - '[message] <yellow>Welcome to our town, <player>!'
```

### Why Individual Files?
- **Crash Proof:** If one NPC file is damaged, none of the other NPCs are affected.
- **Easy Backup & Transfer:** To copy an NPC to another world or server, simply copy its `.yml` file across.
- **Manual Editing:** You can edit positions, actions, or text directly in the file while the server is running, then run `/coconpc reload`.
